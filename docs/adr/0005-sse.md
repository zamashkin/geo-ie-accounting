# 0005 Server-Sent Events for realtime progress

Status: accepted

## Decision
One SSE stream per org from the API. Worker publishes via Postgres LISTEN/NOTIFY; API fans out to connected clients. Events are typed in `contracts/events.ts`.

## Alternatives
- WebSockets: bidirectional, not needed; more infra (sticky sessions, upgrade handling).
- Polling: simple, but worse UX for import progress.

## Consequences
Reconnect with Last-Event-ID; heartbeat to survive proxies. Multiple API instances each LISTEN, so fan-out works without extra infra.
