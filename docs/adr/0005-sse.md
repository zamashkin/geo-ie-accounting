# 0005 Server-Sent Events for realtime progress

Status: accepted (WS-00, 2026-10-15: no extra libraries; uses Fastify 5.12.7 and pg 8.23.1 from ADR 0002/0003)

## Decision
One SSE stream per org from the API. Worker publishes via Postgres LISTEN/NOTIFY; API fans out to connected clients. Events are typed in `contracts/events.ts`.

Contracts v0 define the event union (`import.progress`, `import.completed`, `rates.backfilled`, `invoice.pdf_ready`), the NOTIFY channel `org_events` and its payload `{ orgId | null, event }`, where `null` means broadcast to every org (rates).

## Alternatives
- WebSockets: bidirectional, not needed; more infra (sticky sessions, upgrade handling).
- Polling: simple, but worse UX for import progress.

## Consequences
Reconnect with Last-Event-ID; heartbeat to survive proxies. Multiple API instances each LISTEN, so fan-out works without extra infra. NOTIFY payloads are limited to 8000 bytes, so events carry ids and counts, never row data.
